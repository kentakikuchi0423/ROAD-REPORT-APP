# 要件定義書：大洲市道路破損通報アプリ

## 1. 目的

愛媛県大洲市の市民が LINE チャットを通じて道路の破損を通報できるシステムを構築する。
参考：愛媛県四国中央市の道路破損通報の導線・考え方。

---

## 2. ユースケース

### 2-1. 市民（通報者）

| # | ユースケース | 概要 |
|---|---|---|
| UC-01 | 通報開始 | LINE でトーク開始または通報メニューをタップ |
| UC-02 | 写真送信（近景） | 破損箇所の近景写真 1 枚を送信 |
| UC-03 | 写真送信（遠景） | 破損箇所の遠景写真 1 枚を送信 |
| UC-04 | 位置情報送信 | LINE 標準の位置情報共有機能で破損箇所を送信 |
| UC-05 | 補足情報入力（任意） | 撮影日付・補足コメント・氏名・電話番号を入力 |
| UC-06 | 通報完了 | 受付番号を受け取り、通報が完了したことを確認 |
| UC-07 | 匿名通報 | 氏名・電話番号未入力のまま通報完了 |

### 2-2. 管理者

| # | ユースケース | 概要 |
|---|---|---|
| UC-10 | ログイン | 管理画面にログインして通報一覧を閲覧 |
| UC-11 | 通報一覧閲覧 | 受付日時・ステータス・場所等でフィルタ・ソート |
| UC-12 | 通報詳細閲覧 | 写真・位置情報・補足情報を確認 |
| UC-13 | ステータス変更 | 未対応 → 対応中 → 対応完了 などに更新 |
| UC-14 | CSV 出力 | 通報一覧を CSV としてダウンロード |
| UC-15 | 写真ダウンロード | 個別または一括で写真を取得 |
| UC-16 | 通報削除 | 対応完了後に管理者が手動削除 |

## 3. 会話フロー概要

```
[開始]
  └─ 利用同意・プライバシーポリシー確認
       └─ 近景写真の送信依頼
            └─ 近景写真受信・保存
                 └─ 遠景写真の送信依頼
                      └─ 遠景写真受信・保存
                           └─ 位置情報の送信依頼
                                └─ 位置情報受信・保存
                                     └─ 任意情報の入力案内
                                          ├─ 撮影日付（任意）
                                          ├─ 補足コメント（任意）
                                          ├─ 氏名（任意）
                                          └─ 電話番号（任意）
                                               └─ 確認メッセージ → 受付番号発行
                                                    └─ [完了]
```

- 会話状態はサーバー側（Cloudflare D1）で管理する
- 各ステップで「スキップ」選択肢を提示する（任意項目）
- 写真・位置情報は受信直後に R2 へ保存する

---

## 4. 入力データ定義

### 4-1. 必須入力

| フィールド | 形式 | 説明 |
|---|---|---|
| `photo_near` | 画像ファイル（JPEG/PNG） | 近景写真 1 枚 |
| `photo_far` | 画像ファイル（JPEG/PNG） | 遠景写真 1 枚 |
| `location_lat` | 数値（緯度） | LINE 位置情報メッセージより取得 |
| `location_lng` | 数値（経度） | LINE 位置情報メッセージより取得 |
| `location_address` | 文字列 | LINE 位置情報の住所テキスト |

### 4-2. 任意入力

| フィールド | 形式 | 説明 |
|---|---|---|
| `photo_date` | 日付文字列（YYYY-MM-DD） | 破損を発見した撮影日付 |
| `note` | テキスト | 補足コメント（最大 500 文字） |
| `reporter_name` | テキスト | 通報者の氏名 |
| `reporter_phone` | テキスト | 通報者の電話番号 |

### 4-3. システム付与

| フィールド | 形式 | 説明 |
|---|---|---|
| `receipt_number` | 文字列（例：OZU-20260325-001） | 受付番号 |
| `status` | Enum | 未対応 / 対応中 / 対応完了 |
| `created_at` | DateTime | 通報日時（UTC） |
| `line_user_id` | 文字列 | LINE ユーザー ID（匿名識別用） |

## 5. 管理画面機能一覧

| 機能 | 詳細 |
|---|---|
| 一覧表示 | 受付番号・受付日時・ステータス・住所の一覧。ページネーション対応 |
| フィルタ・ソート | ステータス・日付範囲でフィルタ、受付日時でソート |
| 詳細表示 | 写真（近景・遠景）・地図・補足情報・対応履歴を表示 |
| ステータス変更 | ドロップダウンまたはボタンで変更、変更日時を記録 |
| CSV 出力 | フィルタ条件に応じた通報一覧を CSV ダウンロード |
| 写真ダウンロード | 詳細画面から個別ダウンロード（R2 署名付き URL） |
| 通報削除 | 確認ダイアログ後に論理削除または物理削除 |
| 認証 | Basic 認証またはパスワード認証（初期実装は簡易認証） |

## 6. 非機能要件

### 6-1. セキュリティ

- LINE Webhook 署名検証（`X-Line-Signature` ヘッダー）
- 管理画面は認証必須
- 画像は R2 に保存し、公開 URL は署名付きに限定
- HTTPS 前提
- 個人情報（氏名・電話番号）をログに出力しない
- 利用同意取得・簡易プライバシーポリシーを会話冒頭に提示

### 6-2. パフォーマンス

- Cloudflare Edge での応答（低レイテンシ）
- 画像は受信直後に R2 へ非同期保存

### 6-3. 可用性・運用

- Cloudflare Workers のサーバーレス構成（スケールアウト不要）
- 対応完了後もデータを保持（管理者が削除するまで残す）
- エラー時はユーザーに再送依頼メッセージを返す

### 6-4. コスト

- Cloudflare Workers / D1 / R2 の無料枠を活用
- LINE Messaging API の無料枠内を想定（小規模運用）

---

## 7. 技術スタック

| 領域 | 採用技術 | 理由 |
|---|---|---|
| ランタイム | Cloudflare Workers | サーバーレス・エッジ実行・無料枠充実 |
| DB | Cloudflare D1 | SQLite ベース・Workers との親和性 |
| ストレージ | Cloudflare R2 | 画像保存・S3 互換・無料枠あり |
| フロントエンド（管理画面） | Cloudflare Pages + TypeScript | Workers との統合が容易 |
| 言語 | TypeScript | 型安全・保守性 |
| LINE 連携 | LINE Messaging API | 公式 SDK または直接 REST 呼び出し |
| 会話状態管理 | Cloudflare D1（sessions テーブル） | サーバー側で状態を一元管理 |
